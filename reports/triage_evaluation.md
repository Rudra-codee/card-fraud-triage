## 1. Scope

This task produces reliable, reproducible **validation-only** metrics for:

* the frozen baseline `gmm_baseline_k1_full` (K=1, full covariance), and
* the shortlisted full-covariance candidates `gmm_k2_full`, `gmm_k3_full`, `gmm_k4_full`, `gmm_k5_full`.

No model was retrained for the metrics. Every model was loaded from its saved `.joblib` artifact and used only to score validation rows. The frozen baseline, the chronological split, and the model-selection results were not modified. Test features and test labels were never loaded. `src/triage_evaluation.py` deliberately avoids `load_processed_data()` because that helper also loads `y_test`.

## 2. Methodology

### 2.1 Scores
`anomaly_score = -gmm.score_samples(X_val)` (negative log-likelihood, via `src/scoring.compute_anomaly_scores`). A higher score means the row is less likely under the legitimate-transaction density, so it is more suspicious.

### 2.2 Score–label alignment
Each model's scores are packed with their `row_id` (`create_score_dataframe`). The rows are then **shuffled on purpose**, and the scores are joined back to the labels by `row_id` with a one-to-one merge (`align_scores_with_labels`). The join raises an error on any duplicated, missing, or unexpected row ID. This means the metrics cannot depend on row order happening to line up.

### 2.3 Metrics
| Metric | Implementation |
| :--- | :--- |
| Average Precision (AP) | `sklearn.metrics.average_precision_score` |
| PR curve | `sklearn.metrics.precision_recall_curve` |
| AP 95% interval | Stratified bootstrap, 1,000 resamples, seed 42 (fraud and legitimate rows resampled separately) |
| ROC-AUC | `sklearn.metrics.roc_auc_score` (context only) |
| Recall @ FPR ≤ 1% / 5% | `sklearn.metrics.roc_curve` + recomputation from predictions (below) |

Accuracy is **not** reported. With 0.10% fraud, flagging nothing at all scores 99.9% accuracy.

### 2.4 Threshold-selection convention (Recall @ FPR)
1. A row is flagged when `anomaly_score >= threshold`.
2. `roc_curve(..., drop_intermediate=False)` gives one candidate threshold per distinct score.
3. We choose the **most permissive (lowest) threshold whose FPR ≤ the limit**.
4. **Ties:** rows with identical scores always receive the same decision. If flagging a tied group would push FPR over the limit, the whole group stays unflagged, so the achieved FPR may be *below* the limit but never above it. This matters here: the validation set has 56,957 rows but only 55,851 distinct scores, because of duplicate feature rows.
5. If no non-empty alert set satisfies the limit, the threshold is `+inf` (no alerts).
6. Recall, FPR, TP and FP are then **recomputed from the actual predictions** and cross-checked against `roc_curve`. The code raises an error if the achieved FPR exceeds the limit.

With 56,900 legitimate validation rows, the limits allow at most **569** false positives at 1% and **2,845** at 5%.

### 4.1 Consistency with the model-selection report
* AP and all recall counts match `reports/gmm_model_selection.md` for every model.
* The **thresholds differ slightly**. Model selection used `np.percentile(legit_scores, 99)`, which interpolates between scores and does not check the achieved FPR. The recall counts happen to be unchanged, but the thresholds in this report are the ones that provably satisfy FPR ≤ 1%. `src/model_selection.py` and its outputs were left unchanged, so this difference is documented here rather than changed silently.

## 5. Audit of the K=4 full-covariance result

The K=4 AP (0.484) is about 6.5× the baseline's. It was **not** assumed to be correct or incorrect; it was checked as follows.

| Question | Check | Result |
| :--- | :--- | :--- |
| Are scores aligned with labels? | Scores shuffled, then joined by `row_id` | AP unchanged (0.4840) |
| Would a misalignment be caught? | Scores shifted by one row | AP collapses to **0.0010** (= fraud rate) |
| Is the AP an artifact of the labels? | 100 label permutations | Mean AP **0.0011**, max 0.0018 |
| Same validation rows as the other models? | Shared `row_ids_val`, manifest check | Yes, 56,957 rows |
| Did labels or validation/test data enter fitting? | `--refit-check`: refit K=4 full on **legitimate training rows only** (`reg_covar=1e-6, n_init=5, random_state=42`) and compare with the saved artifact | Means, covariances and validation scores **bit-identical** (max abs. difference 0.0). A fit that also included the 360 training fraud rows gives different means (max diff 1.62; one-off check, not part of the script) |
| Did test data enter scoring? | Code path | Scoring touches only `X_val.npy`. No test file is opened by the evaluation |
| Scores valid and in the right direction? | Finite, fraud median 169.8 vs legit −1.9 | Yes |

**Audit verdict: the K=4 AP passed.** It is a genuine property of the saved model on this validation set, not an alignment, leakage, or evaluation-path error.

### 5.1 Where the K=4 AP comes from
* **13 of 57** validation fraud cases score above *every* legitimate validation row. The top 10 alerts are 10/10 fraud, the top 100 are 38/100, and the top 500 are 43/500. The baseline's top 100 contain only 4 fraud.
* Beyond the first ~43 fraud cases, K=4 gains nothing. Its Recall @ 5% FPR (82.5%) and ROC-AUC (0.935) are **lower** than the baseline's (87.7%, 0.955).
* Mechanism: K=4 has components whose covariances have eigenvalues clamped at the `reg_covar = 1e-6` floor (4 and 12 such directions in components 1 and 2; see `reports/gmm_model_selection.md` §5). Fraud rows that leave this near-flat legitimate subspace receive extremely large negative log-likelihoods (the largest is 96,758). That is why the top of the ranking is so clean.

### 5.2 Remaining concerns
* **Small fraud count.** With 57 fraud cases, the AP is driven by about 13–38 transactions. The bootstrap 95% interval is wide (0.36 – 0.61). It does not overlap the baseline's interval, but a handful of fraud cases moving would noticeably change the AP.
* **Sensitivity to fit settings.** The behaviour depends on near-singular covariance directions. The earlier `reg_covar` sweep (model-selection report §5.3) kept AP between 0.48 and 0.52 for `1e-6` to `1e-3`, but it fell to 0.28 at `1e-2`. K=5 (AP 0.22) shows the same effect less strongly. Stability across random seeds was **not** tested here, because it would require retraining.
* **Single time window.** Validation is one chronological window. Whether the same fraud patterns leave the legitimate subspace in later periods is unknown, and must not be checked on the test set before the model and threshold are frozen.

## 6. Limitations

* Validation-only results. The test set was untouched, so nothing here estimates final generalisation.
* 57 fraud cases → recall at a fixed FPR moves in steps of 1.75 percentage points per fraud case. Differences of one or two cases (e.g. 42 vs 43 at 1% FPR) are not meaningful.
* AP summarises the whole ranking. Operational usefulness depends on investigator capacity (alerts per day), which this task does not model.
* The AP interval comes from a bootstrap of a single validation window. It reflects sampling noise, not distribution shift.
* The thresholds are calibrated on the same validation rows they are reported on, so the recall at those thresholds is optimistic for future data.

---

## 7. Findings

1. All five models are evaluated on the **same 56,957 validation rows and labels**, aligned by `row_id`, with finite, correctly oriented scores.
2. At fixed FPR the models are **very close**. Recall @ 1% FPR is 42–43 of 57 for every model, and Recall @ 5% FPR is 47–51 of 57. K=2 is highest at 5% FPR (51/57), and K=4 is lowest (47/57).
3. The models differ mainly at the **top of the ranking**. K=4 (AP 0.484) and K=5 (AP 0.219) put far more fraud into the first few hundred alerts than K≤3 (AP 0.074–0.083).
4. The K=4 result **passed the audit**: there is no misalignment and no label, validation or test leakage, and the artifact is reproduced exactly by a legitimate-only refit. Its strength is concentrated in the highest-scoring alerts and comes with the caveats in §5.2.
5. **No final model recommendation is made from AP alone.** Choosing between K=4's top-of-queue precision and K=2's / the baseline's recall at a looser FPR depends on review capacity. That operational analysis is handled separately.
